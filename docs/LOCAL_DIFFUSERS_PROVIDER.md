# Local Diffusers Provider for Echoes Cinema

Status: **PARTIAL / CODE IMPLEMENTED, REAL MODEL EXECUTION NOT YET PROVEN**

This provider is the first canonical local backend intended to replace the
synthetic Cinema proof with clips generated by a real video diffusion model.
It listens on port `8081` by default and implements:

```text
GET  /health
POST /v1/render
```

## Truth gate

The provider reports:

```json
{
  "schema": "echoes.render-provider-health.v1",
  "status": "PASS",
  "backend": "diffusers-local",
  "realModelLoaded": false
}
```

until a Diffusers pipeline has actually loaded in the running process. Render
requests are rejected while `realModelLoaded` is false. Echoes Cinema jobs use
`--require-real-model` by default for HTTP backends, so a missing or failed model
cannot be classified as REAL.

## Windows installation

Use Python 3.10 or another version supported by the chosen PyTorch build.
Install a CUDA-compatible PyTorch build for the installed NVIDIA driver, then:

```powershell
python -m pip install -r providers/requirements-diffusers.txt
```

FFmpeg must be available in `PATH`.

## Start the provider

```powershell
$token = [guid]::NewGuid().ToString("N")
.\scripts\start-diffusers-provider.ps1 `
  -ModelId "<hugging-face-model-id-or-local-path>" `
  -Token $token `
  -Port 8081 `
  -Device cuda `
  -Width 576 `
  -Height 320 `
  -Fps 8 `
  -MaxFrames 24
```

The process loads the model before it can advertise `realModelLoaded=true`.
The initial model download can be large and is not represented as complete until
health confirms the loaded model.

## Verify health

```powershell
$headers = @{ Authorization = "Bearer $token" }
Invoke-RestMethod -Uri "http://127.0.0.1:8081/health" -Headers $headers
```

Required result before a real job:

```text
status          = PASS
backend         = diffusers-local
realModelLoaded = true
modelId         = the configured model
```

## Run the first real Cinema job

Build `RenderManifestCli`, prepare a song-sections CSV, then:

```powershell
.\scripts\run-real-cinema-job.ps1 `
  -SectionsCsv ".\tests\fixtures\cinema_proof_sections.csv" `
  -OutputRoot ".\real-cinema-proof" `
  -ManifestCli ".\build-prompt\Release\RenderManifestCli.exe" `
  -JobId "echoes-first-real-diffusion" `
  -Token $token `
  -AudioFile ".\song.wav"
```

The runner performs:

```text
health real-model gate
-> manifest creation
-> authenticated render requests
-> H.264/yuv420p validation for every clip
-> assembly
-> optional audio mux
-> final QC
-> job-result.json
```

A real success requires all of the following evidence:

- provider health with `realModelLoaded=true`;
- `render-state.json` with every task `PASS`;
- per-clip FFprobe QC;
- final MP4 with H.264/yuv420p;
- optional AAC audio when an audio file was supplied;
- `job-result.json` with `backendStatus=REAL`.

## Current limitations

- The generic provider calls a text-to-video Diffusers pipeline. Model-specific
  pipelines may require an adapter when their call signature differs.
- Reference-image and strong subject-identity controls are declared unsupported
  until a compatible model or adapter consumes those fields.
- The provider serializes GPU inference with one render lock.
- Resolution, frame count, inference steps, and guidance are bounded by provider
  settings to prevent unbounded requests.
